# Проверки

## Команды

- `npm.cmd test` — доменные тесты Vitest.
- `npm.cmd run build` — TypeScript project build и production-сборка Vite.
- `npm.cmd run dev` — локальный просмотр пользовательского интерфейса.
- `npm.cmd run icons` — воспроизведение PNG-иконок.
- В этой среде PowerShell блокирует `npm.ps1`, поэтому используется `npm.cmd`.

После изменения бизнес-логики запускать связанные тесты и production build; не считать успешную сборку проверкой всего пользовательского сценария.

## Автоматически покрываемые сценарии

- обе формулы BMR и все пять коэффициентов активности;
- TDEE, консервативная цель, ручная калорийность, энергооценка БЖУ и невалидные профили;
- расчёт КБЖУ из количеств ингредиентов;
- аллергенные/исключаемые ингредиенты;
- детерминированное меню и дневные итоги;
- локальная замена блюда и случай отсутствия альтернатив;
- объединение ингредиентов в покупках;
- 200 г / упаковка 500 г / 150 ₽: 60 ₽ стоимости использования и 150 ₽ покупки;
- округление упаковок вверх, вычет запасов на уровне расчётной функции и некорректные цены.
- восстановление прежней записи `localStorage` без избранного и сохранение избранного в прежнем ключе;
- повреждённое поле избранного не стирает профиль, меню и отметки покупок; некорректный JSON не перезаписывается автоматически;
- знаковое отклонение калорий от цели и отсутствие расчёта при невалидном целевом значении;
- generated service worker: allowlist кешируемых файлов, offline fallback оболочки, смена версии и отсутствие записи в Cache Storage персональных данных.

## Проверка в браузере

- переходы всех пунктов навигации к правильным секциям, активное состояние и отсутствие горизонтального overflow на ширинах 320, 360, 375, 390, 430, 768 и 1440 px;
- окно рецепта с самым длинным названием текущего каталога на ширине 320 px: края окна в пределах viewport, заголовок и содержимое доступны;
- клавиатурное управление диалогом рецепта: начальный фокус, удержание фокуса, Escape и восстановление фокуса после закрытия;
- профиль → меню → открытие рецепта → замена → список покупок;
- избранное после reload, отметка покупки после reload и восстановление тестовой отметки после проверки.

Реальные Android/iOS-устройства и поведение экранной клавиатуры физического телефона этой автоматизированной средой не проверяются.

Восстановление после повреждённого `localStorage` и квоты проверяется доменными тестами; визуальные пустые состояния и фильтр следует также проверить вручную.

Серверная авторизация/RLS и контроль доступа отсутствуют и потому не тестировались.

## PWA

`npm.cmd run build` создаёт `dist/manifest.webmanifest`, PNG-иконки 192×192, 512×512, maskable 512×512 и Apple touch 180×180, версионированный `dist/sw.js` и precache с фактически построенными JS/CSS ресурсами. Автотест проверяет manifest и PNG signatures/dimensions. В production preview HTTP проверялись `/`, `/manifest.webmanifest`, все иконки и `/sw.js`; сервис-воркер зарегистрировался, управляет открытой страницей, предложил новую версию и успешно активировал её по кнопке обновления. Кэш содержит только app shell/статические assets; браузерная localStorage не очищается.

Офлайн-проверка должна начинаться после успешной загрузки и установки через localhost/HTTPS. Уже открытая оболочка и ресурсы берутся из shell cache; первый визит без сети и сетевые сервисы недоступны. Браузерная эмуляция отключения сети в этой среде не завершила надёжную проверку полного offline reload (load assets failed); helper-fetch подтверждает, что HTML/JS/CSS доступны из precache. Полноценный переход к приложению без сети необходимо подтвердить отдельно на Android Chrome и iOS Safari.
