# Прогресс проекта

## 2026-10-19 — старт проекта, первый функциональный этап

### Аудит

- В корне изначально найден только `AGENTS.md` (полная спецификация, 1 583 строки); кода, package manifest, README, тестов, конфигурации, миграций и Git-репозитория не было.
- На компьютере доступны Node.js/npm и Git. Развёртывание, платные сервисы и подключение внешнего backend не выполнялись.
- Полная спецификация сохранена без изменения в корневом `AGENTS.md`; функциональная карта требований находится в `docs/PRODUCT_SPEC.md`.

### Реализовано

- Создано приложение React + TypeScript + Vite.
- Добавлены профиль взрослого пользователя, валидация, формулы BMR/TDEE, выбор цели и предупреждение об ограничении низкой калорийности.
- Создан каталог из структурированных демонстрационных рецептов с составом и шагами; КБЖУ вычисляются из ингредиентов.
- Добавлены детерминированный персональный план на 1/3/7/14 дней, 2–6 приёмов пищи, фильтрация исключений/аллергенов, просмотр рецепта, избранное в текущей сессии, замена блюда и агрегированный список покупок с чекбоксами.
- Профиль, план и отметки списка покупок сохраняются локально в браузере.
- Добавлен точный расчёт стоимости упаковок в копейках как независимый доменный модуль. Цены в интерфейсе не показываются, пока нет проверенного каталога.
- Добавлена документация и тесты доменных расчётов.

### Проверки

- `npm.cmd test` — успешно: 1 тестовый файл, 19 тестов пройдены.
- `npm.cmd run build` — успешно: strict TypeScript и production-сборка Vite завершились.
- `npm.cmd audit` — 0 уязвимостей после обновления Vitest с уязвимой версии 2 до 5; обновление не потребовало `--force`.
- Локальная проверка браузером: заполнение профиля и сохранение, генерация плана на три дня, просмотр рецепта/КБЖУ, замена блюда, обновление списка покупок, чекбокс покупки и восстановление профиля/плана после перезагрузки.
- Дополнительная проверка на ширине 390 px: профиль, меню и покупки доступны без заметной горизонтальной прокрутки. Ограничение молока исключает соответствующий рецепт; изменение ограничений очищает старый план. Пользовательская цель 1 800 ккал отображается, цены отсутствуют честным предупреждением.
- При замене блюда отмеченные покупки, всё ещё используемые планом, сохраняются; список пересчитывается по оставшимся рецептам.
- Ситуация, когда фильтр оставлял меньше приёмов пищи, чем пользователь выбрал, исправлена: генератор теперь сообщает о недостающей категории, не ослабляя фильтр. Тест регрессии включён.

### Известные ограничения и следующие задачи

- Данные рецептов демонстрационные/вручную внесённые, не проверены по производителям или открытым источникам. Каталога цен нет; суммы/упаковки на экране не имитируются.
- Не готовы: полноценный семейный режим и детские профили; редактирование домашних запасов; подключённые фасовки/цены и бюджет; ручные цели БЖУ; расширенные предпочтения/фильтры; постоянное избранное; сервер/авторизация/удаление аккаунта; импорт/администрирование каталога и юридические тексты.
- Меню из малого демонстрационного набора может существенно не достигать целевой энергии; интерфейс показывает фактическое отклонение и предупреждает, что каталог не покрывает ориентир. Не использовать как полноценный план питания.
- Рабочая папка не является Git-репозиторием. Git-инициализация и коммит не выполнялись.
- При установке `npm.cmd install` npm сообщил, что сценарий установки `esbuild` не был автоматически одобрен инструментом; тесты и сборка всё же выполнились успешно.
- Результат — частичный локальный MVP, не продукт, готовый к публичному запуску.

### Следующий шаг

Продолжить этапом семейных участников и индивидуальных порций либо редактированием домашних запасов с тестами. Затем подготовить проверяемый каталог пищевых источников и товарных цен; не подключать цены/магазин без законного подтверждённого источника. Инструкции по запуску приведены в `README.md`.

## 2026-10-19 — мобильный интерфейс и PWA

### Сделано

- Добавлена мобильная сводка дня с калориями, БЖУ и переходами к рецептам; на ширинах телефона вместо лендинга сразу показывается рабочий dashboard.
- Добавлена нижняя панель «Главная / Меню / Покупки / Профиль» на телефонах, крупные поля профиля и элементы меню, удобный список с остатком непокупленных позиций, пустое состояние и мобильная карточка рецепта.
- Учтены safe-area для верхней и нижней панелей, область нижней навигации, экранная клавиатура и длинные scrollable детали рецепта; подключены локальные системные шрифты без запроса CDN.
- Добавлен standalone web app manifest, самостоятельно генерируемые PNG иконки 192×192/512×512, отдельная полноформатная maskable-иконка и Apple touch 180×180.
- Добавлен production service worker: версия обновляется вместе с построенными JS/CSS, HTML и manifest; shell/static assets precache, личные данные в кэш не попадают, старый shell удаляется при активации обновления. Изменение версии запрашивает явное обновление.
- Добавлены настоящий Android/Chromium `beforeinstallprompt` и отдельная iOS-инструкция Safari → «Поделиться» → «На экран Домой».
- Сохранены локальные профиль, план и отметки покупок. Замена блюда пересчитывает список и сохраняет отметки для оставшихся покупок.
- README и инструкции PWA обновлены.

### Проверки этого этапа

- `npm.cmd test` — финальная серия после всех исправлений: 3 файла, 23 теста пройдены (включая manifest/PNG/iOS install-detection).
- `npm.cmd audit` — 0 известных уязвимостей.
- `npm.cmd run build` — финальная сборка после всех исправлений; TypeScript и Vite завершились успешно.
- Production preview: все HTTP-ресурсы `/`, manifest, 4 PNG-иконки и `sw.js` вернули 200; подписи и размеры иконок проверены. Service worker зарегистрирован, управление страницей подтверждено; update banner отобразился, обновление по кнопке успешно активировалось и заменило версию cache shell.
- Browser Playwright проверил существующий путь: профиль, план на 3 дня, рецепт/КБЖУ, замена блюда, список покупок, отметку, сохранение профиля/плана/галочки после reload.
- Адаптивность была измерена для 320, 375, 390, 430, 768 и 1440 px: горизонтального выхода за ширину окна нет; нижняя навигация отображается до 700 px и имеет область касания >44 px. Перекрытие нижнего nav смягчается safe-area и padding документа.
- Ручная эмуляция offline network в интегрированном браузере вызвала зависший переход/ошибку loading assets; поэтому успешный offline full-page reload не заявляется. Worker precache зарегистрирован и отдавал закэшированные HTML/JS/CSS через fetch, но переход на новый offline page следует повторно проверить в реальном Android Chrome/iOS Safari.

### Ограничения и продолжение

- Публикации и HTTPS-развёртывания не было. Service worker действует только в production и secure context (HTTPS или localhost); первый вход без сети не поддерживается. Chrome/Chromium показывает кнопку только при собственных критериях устанавливаемости. На iOS доступность домашней установки отличается и требует Safari.
- Приложение продолжает использовать демонстрационные непроверенные рецепты и хранить данные только в localStorage текущего браузера. Установка не создаёт аккаунт, не синхронизирует устройства и не гарантирует полного offline-пользования.
- Браузерная среда не является реальным iPhone/Android устройством: виртуальная клавиатура, safe area и установку на физическом Safari/Chrome требуется дополнительно проверить на устройстве.
- Подтверждённые размеры интерфейса в production preview: 320, 375, 390, 430, 768 и 1440 px; горизонтальный overflow не обнаружен; нижняя панель имеет 51 px по высоте интерактивного пункта.
